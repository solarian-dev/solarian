# Controllers

A **Controller** is the node that *decides* what the robot does. It receives [Observations](/docs/observations) from the relay server, computes the next [Action](/docs/actions), and sends it back. Anything that can produce an action — a teleoperator, a hard-coded script, a learned policy, an LLM-driven planner — is a controller. {{ className: 'lead' }}

Defined in [`solarian/core/controller.py`](https://github.com/solarian-dev/solarian/blob/main/solarian/core/controller.py). The class is abstract: subclasses must implement `control_step()`.

## Defining a Controller

Subclass `Controller` and implement `control_step()`:

```python
from solarian.core import Controller
from solarian.core.action import ActionType
from myrobot.action import MyAction

class MyController(Controller):
    def control_step(self) -> MyAction:
        action = MyAction.zeros()
        action.action_type = ActionType.MODULE_ACTION
        # ... fill in action.arm.shoulder_pan.value, etc. ...
        return action
```

The framework calls `control_step()` at `cfg.fps` Hz. Whatever it returns is serialized and pushed to the relay server.

The latest observation is always available as `self.last_observation`, protected by `self.observation_lock` (Solarian's state-receiver thread overwrites it as new observations arrive).

```python
class MyController(Controller):
    def control_step(self) -> MyAction:
        with self.observation_lock:
            obs = self.last_observation
        action = MyAction.zeros()
        action.action_type = ActionType.MODULE_ACTION
        action.arm.shoulder_pan.value = obs.arm.shoulder_pan_pos.value + 0.01
        return action
```

## Registering your Controller class

Set `CONTROLLER_CLASS` in your project's [`settings.py`](/docs/settings):

```python
CONTROLLER_CLASS = 'myrobot.controller.MyController'
```

`solarian run-controller` reads this, imports the class, and instantiates it with the `ControllerConfig` parsed from `conf/controller.yaml`.

  </Property>

  </Property>
  <Property name="device" type="str">
    Torch device (<code>cpu</code>, <code>cuda</code>, <code>mps</code>) for any policy / model the controller loads.
  </Property>
</Properties>

## Lifecycle

When `solarian run-controller` runs, the framework calls:

```text
Controller(cfg)            # __init__ — opens ZMQ sockets, builds shared memory
   │
   ├── connect()           # connect any controller-side modules (leader arms, etc.)
   ├── initialize()        # one-time setup hook
   └── start()             # spawn _state_receiver thread, control_loop thread,
                           # optional pynput keyboard listener, then on_start(),
                           # then display_loop() (or _headless_loop in headless mode)
```

The control loop is split into:

- **`_state_receiver`** (thread) — pulls every incoming `Observation` off the SUB socket and updates `self.last_observation` under a lock.
- **`control_loop`** (thread) — calls `control_step()` at `cfg.fps`, serializes the returned `Action`, and pushes it to the relay server.
- **`display_loop`** (main thread) — opens an OpenCV window per camera and renders the most recent observation. In `headless` mode this is replaced by a stdin loop.

## Keyboard input

Solarian uses [pynput](https://pynput.readthedocs.io/) to capture global keyboard events as long as the controller process is in the foreground. Override these two hooks:

```python
class MyController(Controller):
    def on_key_press(self, char: str):
        """Called once when *char* transitions from released to pressed."""
        ...

    def on_key_release(self, char: str):
        """Called once when *char* transitions from pressed to released."""
        ...
```

Both hooks fire **once per physical key transition**. OS-level auto-repeat (when you hold a key down) does *not* trigger `on_key_press` again — Solarian tracks held keys in an internal set (`_keyboard_held`) and suppresses repeats.

A typical teleop pattern:

```python
class MyController(Controller):
    STEP = 0.05

    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.target = MyAction.zeros()

    def on_key_press(self, char: str):
        if char == 'a':
            self.target.arm.shoulder_pan.value -= self.STEP
        elif char == 'd':
            self.target.arm.shoulder_pan.value += self.STEP
        elif char == 'q':
            self.events["exit_early"] = True

    def control_step(self) -> MyAction:
        self.target.action_type = ActionType.MODULE_ACTION
        return self.target
```

<Note>
  If <code>pynput</code> isn't available (rare — it's pulled in by Solarian's base install), the keyboard hooks silently no-op and the controller still works for non-keyboard inputs.
</Note>

## Controller-side modules

A `Controller` can also attach `Module` instances as class attributes. This is how leader-arm teleoperation works: the *controller* hardware (a small follower arm you wave around) is itself a Solarian module that streams positions, which the controller then turns into actions for the *real* robot.

```python
class TeleopController(Controller):
    leader = LeaderArmModule()      # controller-side module

    def control_step(self) -> MyAction:
        leader_pos = self.leader.read_positions()
        action = MyAction.zeros()
        action.action_type = ActionType.MODULE_ACTION
        for name, value in zip(action.arm.values(), leader_pos):
            value.value = float(value)
        return action
```

Controller-side modules read their config from `cfg.modules[name]` (i.e. inline under `controller.yaml` rather than from a top-level `conf/<name>.yaml`).

## Lifecycle hooks you can override

<Properties>
  <Property name="initialize()">
    Runs once after <code>connect()</code>. Use for one-time setup that needs a live observation stream (homing, baseline reads, etc.).
  </Property>
  <Property name="on_start()">
    Runs after the receiver and control threads have started but before the display loop. The <code>AIController</code> uses this to start its <code>ThinkProcess</code>.
  </Property>
  <Property name="on_key_press(char)">
    Single-fire keyboard-down hook.
  </Property>
  <Property name="on_key_release(char)">
    Single-fire keyboard-up hook.
  </Property>
  <Property name="control_step()">
    <strong>Required.</strong> Compute and return the next <code>Action</code>.
  </Property>
</Properties>
