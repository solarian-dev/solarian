# IK Calibration & Alignment

IK reasons entirely in the MuJoCo model (radians). On real hardware every joint value passes through two conversions, so a commanded **+X** move only tracks correctly when the real arm and its model agree on what each joint angle means. This page is the guided process for getting there — for operators bringing up an arm, and for authors writing the model. {{ className: 'lead' }}

## Why a real arm mis-tracks

A joint value crosses two mappings before the solver sees it:

1. the servo bus maps **raw encoder units → normalized `[-100, 100]`** using the calibration (`range_min` / `range_max` / `drive_mode`);
2. the [`IKActuatorBus`](/docs/ik) maps **normalized → radians** using the *model's* joint limits `(lo, hi)`.

Composed, for a raw position `P` in `range_m100_100` mode:

```text
rad(P) = ((P - range_min) / (range_max - range_min)) * (hi - lo) + lo
```

So Cartesian moves track correctly only when **`range_min` corresponds to the model's `lo`, `range_max` to `hi`, and `drive_mode` matches the model's positive direction.** If the recorded mechanical range doesn't line up with the model's `jnt_range`, each joint picks up a scale/offset error and a commanded **+X** becomes a skewed blend of X/Y/Z — it moves, but not the way you asked.

<Note>
  Everything here is defined in terms of the normalized <code>[-100, 100]</code> space and the generic <code>MotorCalibration</code>, so it works for <strong>any</strong> servo (Feetech, Dynamixel, …). The only servo-specific input is an optional <em>counts-per-revolution</em> hook used by the quantitative checks; without it the tools fall back to the live visual mirror.
</Note>

## The contract (model authors)

> The MuJoCo model's `jnt_range` for each joint **equals** the real arm's mechanical hard-stop angles.

Anchoring on mechanical hard-stops keeps operator calibration to an easy limit sweep. Correctness then rests on this authoring-time contract, not on the operator. Tighter software limits, if you want them, live in `SafetyConfig` (`pos_min` / `pos_max`), **not** in the model.

### Derive model limits from the real arm

Run a sweep (or read an existing calibration) and get MJCF-ready `jnt_range` values in radians:

```bash
solarian derive-model-limits          # reads the existing calibration
solarian derive-model-limits sweep=true   # guided live limit sweep
```

Paste the printed `range="lo hi"` values into the arm's MJCF `<joint>` elements, and keep the module yaml's `sim.range_min` / `sim.range_max` in sync (they must equal the model range).

### Verify the match

```bash
solarian verify-ik-calibration
```

This converts each joint's calibrated span to radians and compares it to the model's `jnt_range`, printing a per-joint table and an overall **PASS/FAIL**:

- **mismatch** — model range ≠ real mechanical range → re-run `derive-model-limits` (or the sweep).
- **continuous** — a joint with no hard stop (see below) → handled by the reference-pose fallback.
- **unknown** — the servo reports no encoder resolution → verify with the live mirror instead.

## The operator flow

The easy limit sweep is unchanged — `solarian calibrate-module` records `range_min` / `range_max` and homing for every joint. On top of that, `calibrate-ik` fixes the sim↔real correspondence with a live MuJoCo view shown **alongside** the real arm:

```bash
solarian calibrate-module   # 1) limit sweep (records ranges + homing)
solarian calibrate-ik       # 2) guided sim<->real alignment
```

`calibrate-ik` walks three steps:

1. **Live mirror** — move the real arm by hand; the on-screen sim arm must follow it 1:1. This is the intuitive "did it work?" check.
2. **Sign check** — for each joint, confirm the sim moves the *same* direction as the real joint. If it's reversed, the tool flips that joint's `drive_mode` and saves — no pose-matching required.
3. **Cartesian check** (optional) — commands small pure **+X / +Y / +Z** tool moves and asks you to confirm the direction (and optionally measure the distance). A wrong direction points at a joint sign; a wrong distance points at the model `jnt_range`.

### Continuous (no hard-stop) joints

Some joints — e.g. a `wrist_roll` that spins ~full-turn — have no mechanical stop, so "move to the limit" is undefined. `verify-ik-calibration` flags these automatically (a near-`2π` span against a smaller model range), and the guided flow captures a **reference pose** for them instead of a sweep. A module declares them so the tooling knows:

```python
class ArmModule(Module):
    # joints without a usable hard stop
    ik_continuous_joints = ["wrist_roll"]
    # easy, unambiguous reference poses (normalized units)
    ik_reference_poses = {
        "zero": {name: 0.0 for name in JOINTS},
        "bent": {"shoulder_lift": 50.0, "elbow_flex": 50.0, ...},
    }
```

## Command reference

<Properties>
  <Property name="solarian calibrate-ik" type="operator">
    Guided sim↔real alignment: live mirror + per-joint sign check + optional Cartesian check. Saves the corrected calibration.
  </Property>
  <Property name="solarian verify-ik-calibration" type="operator / author">
    Compares the calibrated joint spans to the model <code>jnt_range</code> and reports per-joint PASS/FAIL. Runs offline from the calibration JSON.
  </Property>
  <Property name="solarian derive-model-limits" type="author">
    Prints MJCF-ready <code>jnt_range</code> radians from the real arm's mechanical range (existing calibration or a live sweep).
  </Property>
</Properties>

## Under the hood

- Alignment math (I/O-free, servo-agnostic): [`solarian/core/ik/alignment.py`](https://github.com/solarian-dev/solarian/blob/main/solarian/core/ik/alignment.py) — span↔radian, `verify_model_limits`, `derive_model_limits`, and a two-pose fallback for continuous joints.
- Live mirror infra: [`solarian/sim/mirror.py`](https://github.com/solarian-dev/solarian/blob/main/solarian/sim/mirror.py) — runs a MuJoCo world + viewer next to the connected real hardware without overriding the module bus.
- Cartesian verification: [`solarian/core/ik/verify.py`](https://github.com/solarian-dev/solarian/blob/main/solarian/core/ik/verify.py) — a pluggable `Verifier` (human now, camera/fiducial later).
- The servo-agnostic angular hook lives on `ActuatorBus.counts_per_revolution`; the Feetech plugin implements it from its resolution table.
