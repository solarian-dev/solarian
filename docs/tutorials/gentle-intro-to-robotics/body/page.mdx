# The robot's body

A robot arm is a chain of rigid parts moved by motors. This chapter names the parts and counts the ways they can move. By the end you can read the Solarian Arm 1 as a list of six joints, which is exactly how Solarian describes it. {{ className: 'lead' }}

## Links, joints, and the end effector

A **manipulator** is a chain of rigid **links** (solid bodies) connected by **joints**. The first link is the **base**, usually bolted to a table or a mobile base. Each joint moves every link after it. The last link carries the **end effector**: the part that touches the world.

<ManipulatorFigure />

What goes on the **end effector** depends on the job:

- A **gripper** closes on an object. The simplest is a **parallel gripper**, two fingers that slide toward each other. This tutorial uses one.
- A **hand** has several fingers. It holds more shapes, it has more dexterity, and needs many more motors.
- A **tool** does one job: a screwdriver, a suction cup, a pen.

A camera often rides next to the gripper, so the robot sees what its hand sees.

## Degrees of freedom

A **degree of freedom** (DoF) is one independent way to move a body. An object floating in space has six: it can slide along x, y, and z, and it can rotate about x, y, and z.

<DofFigure />

A joint connects two links and by doing so it adds constrains that only alllow some of those degrees of freedom. The **two kinds of joints** you meet most:

- A **revolute** joint is a hinge. It keeps one rotation DoF, and its value is an angle.
- A **prismatic** joint is a slide. It keeps one translation DoF, and its value is a distance.

An arm's elbow is a revolute joint. The fingers of a parallel gripper slide on prismatic joints:

<JointTypesFigure />

Each of these joints adds one degree of freedom to the chain. Count the joints and you have counted the arm's degrees of freedom.

## Actuators

Every joint needs something to drive it. That part is the **actuator**, and on a typical arm it is an electric motor or servo.

A bare **motor** only spins: fast, with little force, and blind to its own angle. A **servo** puts three more parts in the same box as the motor:

- a **gearbox**, which trades speed for force by combining gears;
- a **sensor**, often a magnetic **encoder**, which measures the angle of the output shaft;
- a small **controller**, which runs the motor until the sensor reads the angle you asked for.

<ServoFigure />

The controller compares the target with the encoder's reading and powers the motor according to the error. A large error gets full power. As the output closes in, the error shrinks, the power drops, and the output settles on the target.

So you send a servo a target angle, and it moves there and holds. It also reports the angle it reached, which is how the robot knows its own pose.

A servo drives one joint. Its body is bolted to one link, and its output shaft turns the next link. On the Solarian Arm 1 every joint has its own servo.

## The Solarian Arm 1: six joints

The Solarian Arm 1 is the arm this course uses. Here is its real simulation model, the same MuJoCo file Solarian loads, with the solarian-gripper1 mounted on the end. Each slider drives one joint, the way a command to its servo would.

<Arm1Figure />

The arm and the gripper are two separate pieces of hardware, bolted together at the arm's **flange**, the mounting plate at the end of the wrist. Solarian models them the same way: two modules, `arm` and `gripper`, each with its own servos. A different gripper means a different gripper module, and the arm module stays as it is.

The arm has six revolute joints, from the base out to the wrist:

| Joint | Motion |
| --- | --- |
| `shoulder_pan` | turns the whole arm left and right |
| `shoulder_lift` | raises and lowers the upper arm |
| `elbow_flex` | bends the elbow |
| `wrist_flex` | tilts the hand up and down |
| `wrist_yaw` | swings the hand sideways |
| `wrist_roll` | spins the hand around its own axis |

**Six revolute joints give the arm six degrees of freedom**. The gripper adds a seventh motion, the gap between the fingers, driven by its own servo.

### Why six

To pick something up, the hand has to arrive at a **position**, three numbers, and at an **orientation**, three more. A cup handle, a screw, and a block that has to face the camera all care about the orientation.

With three joints the arm can reach a point, and the hand arrives turned however the arm happens to fold. With six joints the arm can choose the point and the orientation together. That is why six is the standard count for a manipulator. Arms with seven or more degrees of freedom exist. The extra joints let them reach the same pose in more than one way, which helps on a crowded space (eg: to avoid collisions with other objects).

## In Solarian

The whole machine is a [`Robot`](/docs/robots). Each piece of hardware on it is a [`Module`](/docs/modules): the arm, the gripper, the camera. A module has its own control loop and its own config file.

A module declares its joints as class attributes, one per joint, along with the actuator that drives it. Here is the arm you write in [Tutorial 2](/docs/tutorials/first-robot/arm), with the six joints from the table:

```python {{ title: 'my_robot/modules/my_arm_module.py' }}
from solarian.core.arm_module import ArmModule
from solarian_feetech.actuator import FeetechServo


class MyArmModule(ArmModule):
    shoulder_pan = FeetechServo(model="sts3250")
    shoulder_lift = FeetechServo(model="sts3250")
    elbow_flex = FeetechServo(model="sts3250")
    wrist_flex = FeetechServo(model="sts3250")
    wrist_yaw = FeetechServo(model="sts3215")
    wrist_roll = FeetechServo(model="sts3215")
```

Each `FeetechServo` is one servo, so each line is one joint. `sts3250` and `sts3215` are two Feetech servo models: the stronger one carries the shoulder, elbow, and wrist flex.

The gripper follows the same pattern. It ships in a plugin, so you install it instead of writing it. Its module declares a single servo:

```python {{ title: 'solarian_gripper1/gripper_feetech.py' }}
class Gripper1FeetechModule(GripperModule):
    gripper = FeetechServo(model="sts3215")
```

The robot lists its modules the same way:

```python {{ title: 'my_robot/robot.py' }}
class MyRobotRobot(Robot):
    arm = MyArmModule()
    gripper = Gripper1FeetechModule()
```

The attribute names, `arm` and `gripper`, are the names you use from then on: in config files, in commands, and in recorded data.
