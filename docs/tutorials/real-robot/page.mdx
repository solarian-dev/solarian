# The real robot

Tutorial 2 was the project. This one is the same project on a desk: printed parts, Feetech servos, a Raspberry Pi, and the keyboard you already wrote. You do not create a second codebase. Dropping `--sim` from `solarian run-robot` is the switch. {{ className: 'lead' }}

Finish [Tutorial 2](/docs/tutorials/first-robot) first. Simulation keeps working afterward: `solarian run-robot --sim` still runs the same class in MuJoCo.

## Chapters

1. [Parts](/docs/tutorials/real-robot/parts) — what to buy, from the hardware pages.
2. [Assemble](/docs/tutorials/real-robot/assemble) — the arm, then the gripper and camera.
3. [Computer](/docs/tutorials/real-robot/computer) — the Pi, the serial port, a deployment file.
4. [Calibrate](/docs/tutorials/real-robot/calibrate) — servo ranges and direction. Not the camera yet.
5. [Drive it](/docs/tutorials/real-robot/drive) — the keyboard, on the metal.
6. [Real camera](/docs/tutorials/real-robot/camera) — picamera2, and the live image in the controller.

## Two calibrations, on purpose

`solarian calibrate` records how far each servo turns and which way is which. That is this tutorial. It makes the keyboard on the real arm match the keyboard in sim.

Hand-eye calibration — where the camera sits relative to the fingertips — waits for [Tutorial 4](/docs/tutorials/skills/real-arm). A policy that reaches for something it sees is wrong without it. Joint teleop is not. Doing both in one sitting is how a working arm gets blamed on a bad policy, or the other way around.

## While you work

The arm can pinch and it can swing into itself. Start with a clear table, one hand on Control-C, and the other off the linkage. The first motion after torque comes on should be a small one: a single `s`, watched, then stop. The drive chapter says when to kill torque. Read it before you energize the bus.
