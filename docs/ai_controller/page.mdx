# AI Controller

The AIController extends the base Controller class and implements a dual-process cognitive architecture:

Key Components:
Component	Rate	Role
Controller	Base class	Handles ZMQ communication, threading, display
AIController	-	Orchestrates System1 and System2
System1	~30 Hz (FPS)	Fast reactions, skill execution
System2	~1 Hz (TPS)	Slow reasoning via VLM

Data Flow:
1. Robot → Controller: Observation via ZMQ
2. Controller → System1: control_step(observation)
3. System1 ↔ System2: Events sent via attend(), actions received via get_actions()
4. System1 → Controller: LowLevelAction returned
4. Controller → Robot: Action sent via ZMQ

Key Design Decisions:
- System2 runs in a daemon thread started in connect() - always thinking in background
- System1 is synchronous with the control loop - reacts at frame rate
- Communication is asynchronous: System1 notifies System2 of events, System2 queues actions when ready
- Skills bridge high-level to low-level: HighLevelAction contains a Skill that executes to produce LowLevelAction

Key Insight: This is a dual-process architecture inspired by Kahneman's System 1/System 2 theory:
  • System 1 (Fast): Reactive, runs at sensor rate (~30Hz), handles immediate responses
  • System 2 (Slow): Deliberative, runs at ~1Hz, uses VLM for reasoning and planning




## See Also
- [Server](/server): The server node acts as a bridge between the robot and the controller. It runs on a remote machine and is responsible for receiving actuator commands from the controller and forwarding them to the robot, as well as receiving sensor data from the robot and forwarding it to the controller.
- [Robot](/robots): The robot node runs on the robot and is responsible for collecting sensor data and sending it to the server. It also receives actuator commands from the server and executes them on the robot.
- [Observation](/observations): The observation node runs on the robot and is responsible for collecting sensor data and sending it to the server. It also receives actuator commands from the server and executes them on the robot.
- [Action](/actions): The action node runs on the robot and is responsible for collecting sensor data and sending it to the server. It also receives actuator commands from the server and executes them on the robot.
